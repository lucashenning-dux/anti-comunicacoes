Levar para o SendGrid

Passo 1

Um Dynamic Template por arquivo

Email API → Dynamic Templates → Create. Cole o HTML no Code Editor (não no Design Editor, que reescreve o markup). O assunto vai no campo Subject, separado do corpo.

Passo 2

Handlebars, não substitution tags

As variáveis já estão no formato {{first_name}}, que é o dos Dynamic Templates. Cole o JSON de exemplo em Test Data para ver o preview preenchido.

Passo 3

Disparo pelo backend

Cada mudança de estado chama a Mail Send API com o template_id e o objeto dynamic_template_data. O mesmo evento que cria a notificação in-app dispara o email.

Passo 4

IP e domínio separados

Transacional e marketing em subdomínios distintos, com unsubscribe group só no marketing. Emails de serviço não podem cair no mesmo grupo de opt-out da conta ativa.

Um ajuste de premissa

O SendGrid não importa XML. O que ele aceita é HTML colado no editor de código de um Dynamic Template, ou criado via API (POST /v3/templates/{id}/versions) com o HTML no corpo do JSON. É por isso que cada email aqui é um arquivo .html autocontido: nada de CSS externo, nada de imagem hospedada, nada de <div> onde cliente antigo precisa de tabela.
