O layout — oito blocos, um por função

  1. Cabeçalho22px 40px · fundo ink #171717Faixa preta com o wordmark e uma etiqueta de contexto em mono (Proposta, Segurança, Acao necessária). A etiqueta é o que o usuário lê antes do assunto no preview do cliente de email.
  2. SobretítuloIBM Plex Mono 10px · caps · 0.12emClassifica o email em duas palavras. Mesma taxonomia dos cards da Central de Notificações.
  3. TítuloIBM Plex Sans 700 · 26px · -0.5pxUma frase, sujeito e verbo, no indicativo. Nunca uma pergunta.
  4. CorpoInter 15px · 1.65 · #52525bUm parágrafo. Diz o que aconteceu e o que muda para o usuário.
  5. Bloco de dadosMono 11px caps / Plex Sans 700 14pxPares rótulo/valor separados por hairline. É o que substitui o print da tela: valor, pedido, sacado, prazo.
  6. DestaqueFundo zinc + barra 3px semânticaSó aparece quando existe motivo, risco ou aviso. Vermelho para rejeição e falha, âmbar para prazo e cancelamento.
  7. BotãoPílula amarela #e9fc00 · ink 700 13pxUm único CTA por email, sempre levando para a tela correspondente no app.
  8. RodapéMono 9–11px · #8a8a90Assinatura ANTI · uma empresa DUX, canal de suporte, o aviso antifraude e os dados legais da emissora.

Levar para o SendGrid

Passo 1

Um Dynamic Template por arquivo

Email API → Dynamic Templates → Create. Cole o HTML no Code Editor (não no Design Editor, que reescreve o markup). O assunto vai no campo Subject, separado do corpo.

Passo 2

Handlebars, não substitution tags

As variáveis já estão no formato {{first_name}}, que é o dos Dynamic Templates. Cole o JSON de exemplo em Test Data para ver o preview preenchido.

Passo 3

Disparo pelo backend

Cada mudança de estado chama a Mail Send API com o template_id e o objeto dynamic_template_data. O mesmo evento que cria a notificação in-app dispara o email.

Passo 4

IP e domínio separados

Transacional e marketing em subdomínios distintos, com unsubscribe group só no marketing. Emails de serviço não podem cair no mesmo grupo de opt-out da conta ativa.

Um ajuste de premissa

O SendGrid não importa XML. O que ele aceita é HTML colado no editor de código de um Dynamic Template, ou criado via API (POST /v3/templates/{id}/versions) com o HTML no corpo do JSON. É por isso que cada email aqui é um arquivo .html autocontido: nada de CSS externo, nada de imagem hospedada, nada de <div> onde cliente antigo precisa de tabela.
